# Local diagnostic bundles, v1

Implements item 4 of [#112](https://github.com/Cujuju/spillway/issues/112), `arc/request-observability`. This is a diagnostic snapshot, not portable interaction history. It has no importer, upload, issue posting, configuration transfer or archive-wide export.

Open an exchange in Activity → Traces and choose the bundle icon, or tick up to 20 request rows in Traces and choose **Diagnostic bundle**. Picks keep full trace identities across branches and pages, even if retention subsequently removes them. The dialog permits deselection before collection.

## Inclusion and privacy policy

Metadata-only bundles are useful by default. Bodies and arbitrary error/supervisor messages are two separate opt-ins. Neither option enables capture, renews retention or reads client-log prompts. Previously captured bodies retained after capture is turned off remain eligible until archive retention/deletion removes them. Each worker call obtains one selected exchange and relevant attempts in a transaction; the complete collection is a sequence of these snapshots, not a single global database snapshot.

The Activity worker remains the only database owner. Diagnostics calls `diagnosticSnapshot(traceId, includeBodies)`, which calls the existing archive store and reads proxy Activity events with the exact full trace ID using the `requests_by_trace` expression index. Link availability is checked independently of the 200-row page so beyond-page rows are not counted as missing or counted twice as omitted. It never opens another process's live database, scans client logs, or correlates reusable Activity row IDs/timestamps. Optional nested archive-attempt provenance can supply allowlisted model, effort, session and transport facts when the Activity row has expired. Old links remain explicitly unknown. Such fallback does not supply or infer an account or raw error.

All metadata is constructed field by field. Credentials, auth files, client and management keys, database keys, raw config files, environment, headers, query strings, endpoints, executable paths, free-form user agents and credential notes are outside the allowlist. No auth file is read. Known app/database/client/management secrets are used only as in-memory redaction patterns, never included. The display email toggle is not used for sanitization: the preview shows the actual serialized export text.

Accounts, previous accounts, conversations, parents, requests and selections receive separate bundle-local aliases (`account-1`, `conversation-1`, etc.). The same account alias is used for a move's source and another attempt's destination. There is no reverse mapping in the bundle. Trace IDs and archive capture provenance remain stable for explicit archive lookup; they can correlate activity and should be shared deliberately.

### Exact metadata allowlist

- Envelope: `format`, `schemaVersion`, `createdAt`, `warning`, `policy`, `versions`, `counts`, `archiveHealth`, `settings`, `supervisor`, `records`.
- Versions (app and nullable proxy): `version`, `build`, `modified`, `builtAt`; plus proxy state. No PID, path, endpoint or raw process error.
- Capture health: `dropped`, `gaps`, `restarts`, `rejected`, `countersOverlap`. Drops and gaps overlap and must not be added.
- Each available record: stable `id`, `traceId`, durable `cursor`, normalized `at`, `availability`, `partial`; `capture` containing `schemaVersion`, `state`, bounded reason code, capture `id`, `epoch`, `sequence`, `storedBytes`, `format`, decoded flags, bounded content-type/encoding labels; `provider`, `requestedModel`, `client`, aliased `conversation`, allowlisted `method`, `route`, `downstreamStatus`, `attempts`, `attemptsOmitted`, `attemptsUnavailable`, `attemptLinksAtRetentionLimit`, `bodies`.
- Routes: `/v1/messages`, `/v1/responses`, `/v1/chat/completions`, `/backend-api/codex/responses`, `/responses`, `/chat/completions`; all others become null. Methods: GET, POST, PUT, DELETE, PATCH, HEAD, OPTIONS; all others become null.
- Attempts: aliases `request`, `selection`, `account`, `movedFromAccount`, `conversation`, `parentConversation`; `at`, `provider`, `client`, `requestedModel`, `effectiveModel`, `reasoningEffort`, `metadataSource`, nullable `stream`, `failed`, `statusCode`, `errorClass`, nullable `errorMessage`, measured `latencyMs`, `ttftMs`, token counts `inputTokens`, `outputTokens`, `cachedTokens`, `cacheWriteTokens`, normalized `downstreamTransport`, `upstreamTransport`, `transportFallbackReason`. No raw account/auth index, upstream ID or user agent. `errorMessage` is null unless messages are explicitly selected.
- Error classes: rate-limit, authentication, permission, canceled, timeout, connection, server, client, unknown; null for attempts without an observed failure. These are diagnostic classifications, not semantic task outcomes.
- Settings: `proxy.autoStart`, `allowLan`, `strategy`, `apiKeyOrder`, `sessionAffinity`, `sessionAffinityTtlMinutes`, `sessionHoldMinutes`, `restartOnCrash`, `serverErrors`, `firstByteTimeoutSeconds`, `usageLookupSettleSeconds`, `requestLog`, `clientDrift`; `activity.retentionDays`; archive policy `captureBodies`, `retentionDays`, `maxBytes`. No other settings are exported, including port, executable path, preferred accounts, tray identities or ZIP code.
- Supervisor: the last 100 **in-memory app stream** lines, timestamps and fixed event classifications. This is a **limited supervisor summary**, not full diagnostic logs. stdout, stderr and disk log files are always excluded. The separate messages opt-in adds bounded redacted app messages and attempt errors. Section counts disclose lines omitted, redacted and truncated.

Labels are bounded to 160 characters. Optional messages are bounded to 4096 characters. ANSI color sequences and control/directional characters are normalized before redaction, so they cannot reconstruct an unredacted token after matching. Recognizable bearer/basic tokens, JWTs, common key formats, email addresses, URLs, local path patterns and key/value secret patterns are removed. Email scanning tokenizes once to avoid repeated matching over hostile text prefixes. These rules supplement structural exclusion; they do not certify arbitrary metadata labels or text as secret-free.

### Optional body transformation

Only already-retained, supported decoded textual HTTP JSON/SSE or textual WebSocket application messages are eligible. Headers/query strings/provider-hidden content remain outside capture. JSON is parsed and rebuilt recursively; fields whose normalized names identify authorization/authentication, credentials, passwords, secrets, cookies, headers, keys, auth files or tokens (including generic names ending in `token`, such as `session_token` and `csrfToken`) are dropped. Plural token accounting names such as `input_tokens` remain eligible. Arrays/object fields are capped at 1000, nodes at 10,000, nesting at 24, strings at 64 KiB, and individual input payloads at 1 MiB. Secret-bearing object keys are also excluded. SSE exports parsed JSON data packets, not protocol lines; malformed packets are omitted and marked partial. WebSocket exports frame index, direction, timestamp, type, truncation and transformed payload. Binary frames and undecoded/unparseable content are omitted explicitly. Original protocol bytes are not a diagnostic export format.

This is structural sanitization, **not detection of all arbitrary prompt secrets**. Prompt text, tool arguments, completions and free-form error/supervisor messages can contain unknown secrets. They require the user's inspection of the exact JSON pages before saving or sharing. The save action requires an inspection acknowledgment. Content is displayed as Solid text, never HTML, Markdown or executable filenames.

## Format and counts

The file is UTF-8 JSON with a final newline, `format: "spillway-diagnostic-bundle"`, `schemaVersion: 1`. It is intended for inspection with a text/JSON viewer. No archive entries become filenames or filesystem paths. The default filename uses a fixed prefix, generated UTC timestamp and random suffix.

`counts.selected` is the number of distinct selected traces. `included` counts available metadata records; `unavailable` counts identities no longer retained. `partial` counts available records with partial/pending capture, lost/bounded attempt metadata, truncated labels or body export limits. `redacted` counts records with value transformations, including identity aliases. `omitted` counts records deselected in this dialog; the entire rest of the archive is out of scope, not implicitly counted. Counts overlap.

Body counts are separate: `bodiesIncluded` counts records with some transformed content, `bodiesUnavailable` counts records whose capture/identity is unavailable, and `bodiesOmitted` counts available captures excluded by export selection or format/size policy. Each record retains capture `state` independently of body export `disposition` (`included`, `unavailable`, `omitted`), reason and partial flag. A complete capture can have omitted bodies. An expired capture is unavailable rather than export-omitted. A body may be included partially. No HTTP status or capture state certifies task success; `policy.semanticOutcome` is `not-evaluated`.

`attemptsUnavailable` counts retained links lacking full Activity metadata, including links with a partial provenance fallback. `attemptsOmitted` counts known rows/links beyond the 200-attempt record cap. Retained links themselves are capped upstream; reaching that limit is explicit and treated as partial. Missing identities remain a record with `availability: "unavailable"`, `captureState: "unknown"`, and an explanation, never guessed payload.

## Bounds, preview lifecycle and save behavior

At most 20 explicit records and 200 attempts per record are collected. Transformed body content is capped at 256 KiB per record. The complete pretty-printed JSON is capped at 8 MiB. If necessary, bodies are omitted starting at the end of the selected list and marked `total-export-byte-limit`; metadata exceeding 8 MiB rejects preparation and asks for fewer records. One collection/save operation runs at a time. A disposable **formatting-only worker** sanitizes one raw record at a time and serializes the bounded output; it has no database connection, capture pipeline or file I/O. Raw decrypted records do not accumulate across the selection. Cancellation terminates formatting even during CPU work, leaving Electron IPC responsive. At most two prepared previews (at most 16 MiB of serialized text total) are retained for five minutes; preparing a third evicts the oldest. A timer removes expired previews, and closing/changing the dialog cancels collection and discards its preview. No persistent plaintext spool is created for collection.

IPC exposes `diagnosticPrepare(selection)`, `diagnosticDiscard(tokenOrOperationId)`, and `diagnosticSave(token)`. Prepare returns a random opaque token, expiry, byte count, fixed filename, counts and exact JSON. Save accepts only that token, never renderer-supplied content or paths. It opens a native save dialog. The serialized snapshot is frozen: archive expiry/updates after preview cannot change saved bytes. Re-preparing re-reads current availability. Each trace's unavailable/partial state is captured at collection.

Save requires a new absolute `.json` destination from the dialog, rejects Windows alternate streams/control characters, and never overwrites an existing file or symlink. A randomly named exclusive temporary file in the chosen directory is written with restrictive permissions, synced, and published using an exclusive hard link; then its temporary name is removed. Filesystems that do not support this operation return an I/O error without an overwrite fallback. Cancellation is checked before collection calls and file publication; an already published file is committed. A save cancellation keeps the dialog open until the authoritative result arrives, so a file committed during the cancellation race is still reported as saved. Dialog cancellation writes nothing. Write/link failures clean temporary files and retain the reviewed preview for retry. Expired/canceled previews require preparation and inspection again. Shutdown aborts active work, clears cached previews, and awaits any active file write/temporary-file cleanup alongside the existing Activity drain before quitting. Forced process termination or filesystem cleanup failures cannot guarantee removal. No production proxy/app restart, auth/config mutation or automatic upload is involved.

The one authorized Claude Opus 5.5 medium review found seven issues. Direct fixes cover normalization/redaction bypasses, CPU cancellation and raw-record memory accumulation, indexed trace lookups, generic token fields, beyond-page attempt accounting, post-publication cancel reporting, and awaited quit cleanup. No second review was requested.
