# Request archive (internal contract v1)

Implements the inspector portion of [#112](https://github.com/Cujuju/spillway/issues/112) and relates to #38. Capture is opt-in; client-log imports remain metadata-only.

The Activity worker alone owns `archive_entries`, `archive_attempts`, `archive_threads`, `archive_pieces`, `archive_pins`, `archive_search` (contentless FTS5) and `archive_meta` in the existing encrypted `activity.db`. Encryption and key recovery follow `openActivityDb`; neither a plaintext body spool nor a separate database key is created. The renderer never opens the database. Future portable-export, diagnostic and trace features should use the worker API rather than opening a live database from another process.

## Identity and export-facing schema

Types are in `src/shared/archive.ts`. `ArchiveEntry.schemaVersion` is `1`. `id` is `trace:<full inbound trace ID>`, `traceId` is the exact desktop SSE `trace_id`, and nullable `captureId` is the proxy's capture UUID. `captureEpoch` and `captureSequence` preserve provenance after body expiry. Neither identity uses Activity's reusable SQLite row ID or short log filename IDs. One inbound exchange can have many upstream attempts; `ArchiveDetail.attempts` retains requestId/selectionId/at for up to 200 displayed attempts. These are execution identifiers, not alternate body lookup keys.

`ArchiveDetail` adds bounded request/response text, original content-type/encoding labels, requestDecoded/responseDecoded flags, format (`http` or `websocket`), structured frames and attempt links. Bodies are decoded downstream HTTP content or observed downstream application messages, never upstream executor payloads. Empty or absent captures do not imply an empty model conversation. Each frame retains index/direction/time/type/payload/truncated. Received messages and successfully written responses share the connection's full trace; open sockets publish best-effort revisions before closure. No headers or query strings are captured. Body text can itself contain sensitive data; email masking applies to every renderer body and metadata field, but is not a general secret scrubber.

`model`, `provider`, `sessionId` and `client` are populated only from correlated Activity events. These dimensions are unknown if SSE metadata never arrived; they are never inferred from similar timestamps or short IDs. `model` preserves the requested alias. For an inbound exchange with multiple models, the latest correlated attempt supplies the summary dimensions; attempts retain their execution identity. A later trace view can join attempt IDs to its richer metadata.

## Worker and renderer API

- `archiveObserve(ActivityEvent)` records metadata for a real full trace; ignores client imports and absent trace IDs. The live worker's append path calls it, replay-safe.
- `archiveIngest(CapturePage)` commits records, FTS and cursor transactionally. Replay of committed sequences is ignored. Malformed records with trustworthy sequence numbers are skipped and counted as rejected; database write failures roll the entire page back. Invalid page/cursor envelopes report sync errors rather than guessing a cursor.
- `ArchiveStore.query(ArchiveQuery)` (worker-only; portable export pages through it) returns 50 metadata summaries newest first, plus `more`. Pass `archiveCursor(lastEntry)` (serialized `[at,id]` tuple) as `before`, which survives deletion of the cursor row. Filter by literal whitespace-separated keywords (AND), exact sessionId/provider/model/client/state, and inclusive from/to dates. Queries return no bodies. FTS decodes JSON escapes and indexes joined Claude/Codex/OpenAI streaming text fragments while retaining original protocol text for inspection. Search indexes each revision’s new request middle plus response and frames. Common JSON escapes are decoded even in fragments; inherited request text matches the revision where it first appeared. Stable integer search keys survive VACUUM.
- `archiveDetail(traceId)` returns one bounded record or null (unknown). No short-ID fallback.
- `archiveStatus()` returns policy, logical body bytes (`bytes`), budget bytes (`storedBytes`), body-holding threads (`threads`), metadata-only over-budget threads (`overBudgetThreads`), verified full-copy fallbacks (`diffFallbacks`), entry count, epoch, sequence, proxy drop counter, observed sequence gaps, epoch changes and rejected-record count. Renderer IPC supplies syncError; the UI refreshes status and inspector data every three seconds. Drops/gaps overlap and must not be summed.
- `archivePolicy(policy)` normalizes and persists captureBodies/retentionDays/maxBytes; main refreshes the proxy's operational lease. The UI is Settings → Data → Request capture.
- `archiveClear()` deletes bodies/index/identities and resets diagnostic counters while retaining the replay cursor to prevent reimport. Renderer IPC first disables capture and clears the proxy spool; retention/budget choices are preserved. Activity clear deletes archive data and resets diagnostics in the same transaction as Activity data.

These APIs are the integration surface for export/bundle/trace implementations. [Portable archive export v1](portable-archive.md) adds a worker-owned frozen selection and JSONL manifest/capture/trailer API. Existing data-transfer v1 exports Activity metadata only and remains independent. Use `schemaVersion`, stable IDs, explicit state, provenance and bounded detail in consumers; never silently label missing captures complete.

The optional [ClickHouse destination](clickhouse-export.md) exports immutable attempt, capture, settlement and backfill facts through a byte-bounded encrypted outbox. It remains default-off and requires a separate content opt-in; it does not change local accounting or retention.

## Policy and completeness

Default body policy is off, 7 days, 100 MiB. Allowed retention is 1–90 days and stored body budget 1–1024 MiB. HTTP retains at most 256 KiB wire and decoded bytes per direction. The worker decodes identity/gzip/x-gzip/zstd and up to two stacked encodings. Zstd has an 8 MiB decoder window/memory limit. Unsupported/corrupt encodings are explicitly partial with bounded base64 fallback. Invalid UTF-8 replacement can expand stored text. Codex downstream WS limits are 128 application messages per connection, 64 KiB per message and 256 KiB per direction, including negotiated permessage-deflate. Frame/count/byte truncation, failed writes and abnormal disconnects are explicit. Provider-hidden payloads, upstream executor bodies, WS control frames and other WS protocols are outside the support boundary.

Requests use copy/insert/copy diffs against the latest stored request in the same session and model. Entries without a session at first storage get singleton threads. An entry’s thread stays fixed even if later Activity observations change its dimensions. Flat `[pieceId, offset, length]` lists reference immutable, thread-owned zstd level 3 pieces; offsets are UTF-8 byte offsets. Prefix/suffix cut points preserve whole UTF-8 characters. One piece holds new request bytes and one holds response plus frames. Opaque signatures, encrypted reasoning and images remain byte-exact. Readers decompress each referenced piece once and reconstruct the original public detail. Every revision is rebuilt and SHA-256 checked before commit; a mismatch falls back to a verified full copy and increments `diffFallbacks`. An unreadable base uses a full copy.

Retention expires a whole thread by its last activity, so older exchanges in an active thread can outlive retentionDays. Budget counts live threads� compressed pieces plus range-detail JSON, excluding SQLite/FTS overhead and eval-pinned pieces detached from removed threads. Thread totals are maintained on writes and metadata deletion; status sums those totals. Oldest threads are evicted together; their identities remain expired. The thread being written is never evicted to make room for itself. If it alone exceeds the budget, further revisions become metadata only (`missing`, `thread-over-budget`, zero logical bytes). Its flag clears on eviction or a budget change. Up to 20,000 metadata records and 200 attempt links per record survive independently; metadata deletion never deletes thread-owned pieces.

Existing full-detail rows migrate at ArchiveStore construction in `(at,id)` order, eight rows per committed transaction with a durable cursor. The same diff/rebuild path is used. Completion drops the old full-content FTS table and runs incremental vacuum once. Physical encrypted database size can exceed the budget because free pages await reuse/compaction. Migration blocks the Activity worker once at startup. A local encrypted 581-exchange, 362.2 MiB archive measured 27.12 s including database open (21.4 exchanges/s): 9.83 s opening/upgrading the database and 17.29 s in ArchiveStore migration (33.6 exchanges/s). Within migration, storeBody took 4.12 s, dropping the old FTS took 5.27 s, and incremental vacuum took 2.97 s; the remainder includes batch reads, JSON parsing and commits. The final FTS removal/vacuum cost exceeds row conversion and is retained. Migration caches only the most recent base request and avoids rebuilding base responses/frames; the persisted format is unchanged. The migrated database remained 14.3 MiB after compaction, with zero rebuild fallbacks. These are local measurements, not a startup-time guarantee.

Residuals: superseded capture revisions (pending/final and WebSocket snapshots) retain their immutable pieces until thread eviction because later revisions may reference them. Eval cases pin their referenced pieces through eviction and archive clear; case deletion or eval clear releases pins and collects pieces with no live thread. Imported eval cases keep inline snapshots. Eval quotas count rebuilt logical bytes. Archive clear removes threads, bodies and search rows except eval-pinned pieces; Activity clear also removes cases and their pins.

States: absent identity = unknown; metadata-only/known unavailable = missing; awaiting finalization/open WS = pending; bounded/unsupported/interrupted = partial; finalized observed exchange/messages within limits = complete; body deleted by policy = expired. Complete does not certify upstream or semantic completeness. Pending HTTP metadata becomes missing after ten minutes. Worker reopen, proxy epoch change and capture opt-out mark unfinished payload snapshots partial and bodyless records missing; later revisions may replace them. Turning capture off preserves saved bodies until expiry/deletion.

The sync loop renews a 60-second proxy lease every twenty seconds while enabled. Disabled lease is sent once on start/policy transition. Each pass reads at most four pages of four records and durably commits before advancing; a full pass schedules another after 50 ms, otherwise three seconds. Policy edits while the proxy is stopped do not restart polling. Epoch changes reset the cursor and mark unfinished captures explicitly. The bounded memory spool can lose data on overflow/crash/disconnect. Drops, gaps and epoch changes are visible; tail loss may appear only as a drop counter until a later sequence. Restarts before first observation cannot be counted. No losslessness guarantee is made.

The inspector renders masked Solid text, initially 32 KiB per body with incremental chunks in bounded scroll panes. It includes joined response text alongside protocol bodies and live WS message snapshots. Historical Activity and client imports without trace/capture data remain unknown. Capture and existing request-file logging remain independent.

Its thirteen findings were fixed directly; the subsequent requested WS/encoding expansion was self-verified with protocol, opt-in, decoded/frame bounds, corruption and concurrency tests.
