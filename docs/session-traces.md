# Session and subagent trace navigation

Implements Item 5 of [#112](https://github.com/Cujuju/spillway/issues/112), `arc/request-observability`. The Activity worker owns the read model and uses its existing encrypted connection. No second recorder, database, proxy endpoint, or client-log prompt importer is introduced. Capture policy, accounting, affinity and retention are unchanged.

## Node, edge and cost semantics

- A node is an exact nonempty session ID. Without a session, attempts with the same full inbound trace form an unassigned exchange; attempts without either identity remain separate. Full stable proxy attempt identities deduplicate archive links against canonical Activity rows. Reusable SQLite row IDs are not trace identities.
- A parent edge requires an explicit `parentSessionId` on an observation with a known session. Times, similar names, account moves, payload text and HTTP statuses never manufacture edges. A missing parent is an unobserved reference, not a root. Multiple distinct parents are conflicting observations; no winning parent is selected.
- The supported `claude:<native>:agent:<id>` / `codex:<native>:agent:<id>` identity form labels a subagent. Other edge kinds are unknown. The stored fields cannot distinguish a fork from other parent relationships or identify compaction ancestry. An exact captured `responses/compact` endpoint labels that request only. Neither a generic parent link nor a successful HTTP exchange proves task completion.
- Cycles, including self-links, remain visible as evidence warnings. Iterative strongly connected components handle long chains without recursive traversal. Detection covers the bounded read window only; navigating an exact session may exclude its other ancestors.
- Every node reports **own attempts and own usage** only. No subtree totals are calculated. Parent usage is never added to child usage, and selection/trace groups never add another copy of an attempt's tokens or cost. Inbound exchange counts are distinct known full traces within a node, not another request count; do not sum them across nodes if an exchange spans sessions.
- Tokens use existing provider prompt-token conventions plus output. Cached and cache-write counts remain explicit on attempts; missing legacy cache-write fields normalize to zero as in Activity. Cost uses the canonical attempt's exact accounting-ledger cost when available, independently of token-field completeness, preserving recorded historical costs; otherwise existing effective-model list pricing applies. The ledger's zero for an unpriced model is not reported as a known price. Unknown models are unpriced, not free. Cost is an estimate, not subscription billing or an invoice.
- Activity's canonical retained rows are the authority for imported/proxy reconciliation. The trace reader neither reconciles again nor changes the accounting ledger. Imports are included only with `source: 'all'`, visibly labeled. Replay cannot add another copy of a canonical attempt. The worker supplies existing `movedFrom` metadata; the trace reader does not recalculate moves or modify session affinity.
- Archive-only attempt provenance can preserve session/parent, requested/effective model, effort, provider/client, observed failure, measured timing and actual transports. Its `source` must be `proxy`, strings/numbers/booleans are validated, and its enclosing request/time must agree with the archive identity tuple. Old links without provenance stay unassigned even when an exchange summary happens to have a session. No entry-summary attribution is substituted for attempt evidence.
- An archive-only attempt has **unknown tokens, cost and account**, not zero. Aggregate `costUsd` and `tokens` are nullable known subtotals. `missingUsage`, `unpriced`, `unknownOutcomes` and `archiveOnly` make coverage explicit. This reader uses the ledger only for the exact retained canonical attempt; it does not use surviving compact accounting rows to reconstruct missing parent, trace or account-move details. Successful positive measured timings alone contribute to averages, with sample counts. Archived provenance may retain such measurements even after usage detail is gone.

## Worker / renderer API

Types are in `src/shared/sessionTrace.ts`. These methods are exposed through `ActivityLog`, the worker RPC and the generic preload API:

- `traceQuery(TraceQuery): TracePage`: 25 session/exchange nodes, sorted by descending known own cost (unknown last), failed-attempt count, or most recent observation. `nodeId` is exact; `parentSessionId` selects direct children **after** own usage is aggregated, so attempts with missing parent metadata are still counted. `text` is a literal case-insensitive substring over node ID, requested/effective model and effort within the read window. No payload search or body retrieval occurs.
- `traceAttempts(TraceAttemptQuery): TraceAttemptPage`: 50 attempts for one exact node, ordered by `(at, stable attempt identity)` descending, with nullable usage, parent/selection IDs, original account moves, capture state, effective model/effort and transport metadata. No request/response text, headers, query strings or tool payloads are returned. The UI opens the existing `RequestInspector` only on an explicit click.
- Both calls accept inclusive ISO `from`/`to` and `source: 'proxy' | 'all'` (default proxy). Default range is the latest seven days; at most 90 days is accepted. `nodeId` uses `session:<exact session>`, `trace:<exact full trace>` for an unassigned exchange, or `attempt:<stable identity>` for an unassigned historical attempt. Callers should use the returned opaque `next` as `before` and retain their other filters. Cursors bind the range, source and query and survive deletion of their last row; they are not frozen snapshots. Refresh after arrival, reconciliation or retention changes.

The read is a union of retained canonical Activity requests and archive links with no matching retained proxy identity. It selects at most 5,001 metadata candidates per source and merges at most 5,000 for graph/ranking. SQL projects bounded metadata strings and excludes errors/user agents and archive body columns. Indexed time/session/identity queries bound materialized results; narrow date ranges or exact sessions reduce database work. Exact-session attempt paging can reach sessions outside the newest global sample. Parent/keyword filtering and ranking use this bounded observation window; they do not promise to find the lifetime's most expensive branch. Date bounds do not guarantee a fixed CPU budget when many excluded observations share the range.

`coverage` returns normalized dates/source, sampled count, read limit, rejected-link count and an explicit `limited` flag. Limited graphs have partial counts, ranks, links and cycle detection. Each node returns at most 50 sorted parent references (plus full distinct parent count/conflict flag) and 12 model/effort labels (plus truncation flag). Attempt pages use independent stable tuple cursors. A live page can change when reconciliation removes an import, an observation arrives out of order, or retention deletes data; the UI offers refresh and suppresses stale asynchronous replies.

The UI's blank end date follows live traffic on Refresh, while explicitly entered historical dates stay fixed. Pagination and inspector attempt queries pin the last displayed window. Navigated session IDs are displayed masked as metadata, separately from the replacement-session input; editing never submits a masked ID on the user's behalf.

## Coverage limits

Only metadata already observed by Spillway is shown. Capture-only exchanges that never received an attempt link remain in Archive rather than appearing as invented session attempts. Activity retention can remove canonical attempts while archive metadata survives; archive provenance then keeps supported topology navigable, without recovering missing usage. Archive's 20,000-entry / 200-links-per-entry limits and clear operations still apply. Clearing Archive does not delete canonical Activity usage; clearing Activity deletes both.

Capture availability remains unknown/missing/pending/partial/complete/expired under the existing archive contract. “Complete” covers bounded observed downstream bytes/messages, not upstream or semantic completeness. Tools/delegation content is inspectable only when actually present in an explicitly opened capture. Headers, query strings, provider-hidden text and unobserved forks/compactions are unavailable. Every renderer metadata value and inspector body uses existing email masking, and the UI uses theme tokens without adding a proxy status indicator.

Synthetic tests cover parallel/retrying workers, account moves, reconciliation in both arrival orders, replay, late parents, orphan/conflicting/cyclic edges, 5,000-node chains, archive-provenance-only branches, old/malformed provenance, unknown usage/prices, stable paging, explicit read caps and absence of payloads from trace queries.

The one authorized read-only review used Claude Opus 5.5 at medium effort. Its two medium and four low findings were fixed directly: legacy cache-write/cost compatibility, live refresh, neutral HTTP-status wording, normalized unassigned-session filtering, separate masked navigation/input, and explicit missing-query validation. No second review was requested.
